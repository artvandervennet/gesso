Gesso

The primer under everything on vandervennet.art. Tokens, web components and the rules for using them.

Start with the pigments Browse components

Principles

Gesso is the white primer painters brush onto a canvas before any colour goes on. This system does the same job for Art Van der Vennet's portfolio, side projects, slides and CV: a reliable ground, then paint on top.

  1. Prime before you paintEvery page works as plain HTML first. Components wrap real buttons, links and lists, so nothing breaks when JavaScript is slow or off.
  2. One bold stroke per viewChoose one thing to be loud: a painted heading, a drip, a splatter. Everything around it stays quiet and disciplined.
  3. Paint for every eyeEvery colour pairing is contrast-checked by a script. Colour never carries meaning on its own: a branch has a name, a status has a word.
  4. Motion follows the handThings move when someone acts on them. Each page gets at most one reveal of its own. Reduced motion turns all of it off.
  5. Leave visible brushworkStrokes, tape and dabs are slightly irregular on purpose. The irregularity is seeded, so the same stroke paints the same way on every render.

Themes and pigments

Every website picks a theme. A theme is three pigments: a brand colour, a partner that goes with it, and a complement from across the colour wheel. Everything else is generated from those three, so each theme fits together on its own. Try them here.

The three pigments

Each pigment also comes as -light, the version that reads on the deep paint, and -wash, thinned for tinted areas. Names and codes follow the Colour Index printed on paint tubes.

Section paints

Every section of a page gets its own background. The eight paints walk the colour wheel from the brand, through the partner, to the complement, alternating a light and a deeper tint, so no two sections repeat, every drip stands out on the section below, and they still read as one family. Text on paint

On paints 1 to 8, text is the darkest brand shade and links and buttons are the brand colour. On the deep paint, text is gesso white, links are the light partner and buttons are the partner with dark text. The partner is never text on a light paint: it's for strokes, highlights and fills under dark text. The complement is for errors, focus and the odd accent.

Making a theme

Add a recipe to tokens/themes.json and run the build. The generator mixes the shades and the eight paints, then darkens or lightens anything that would fail contrast until every pairing passes AA.

"harbour": {
  "label": "Harbour",
  "brand":      { "name": "Prussian blue",  "code": "PB27", "oklch": [40, 0.09, 238] },
  "partner":    { "name": "Naples yellow",  "code": "PY35", "oklch": [87, 0.09, 92] },
  "complement": { "name": "Cadmium orange", "code": "PO20", "oklch": [60, 0.15, 48] }
}

Then give each website its theme: <html data-theme="harbour">. Without one, a page uses the first theme in the file.

Animation

Motion in Gesso is wet paint: drips that run, colour that soaks in, a dab where you press. It's decoration and feedback only. Content is on the page from the first frame and never waits for an animation to finish.

Animate

  • Decoration: drips running, a stroke being painted, the git graph filling in.
  • Responses to someone's action: a press, a hover, a selection, a theme change.
  • Nothing changes place when you hover over it. Buttons and links respond with paint: a fill, a thicker underline. A canvas may grow slightly, in place, without pushing its neighbours.
  • With the motion tokens below, never with ad-hoc timings.
  • Once per coat of paint. The hero's drips run after the page loads and the header carries them along as they are; the header drips again only when a new section repaints it.

Never

  • Fade, slide or reveal text, images or cards as they scroll in or as the page loads.
  • Delay content or input: no splash screens, no loading animations for decoration, no clicks that wait for an animation.
  • Move, lift or tilt anything on hover, or let a hover shift anything else on the page.
  • Loop forever, or move something while people are reading it.
  • Animate anything when reduced motion is on: every animation then jumps straight to its end state.

Drips run

The hero's wet edge is there at once. With stagger each drip waits a few seconds, then runs down on its own, once. With run they all run together when the drip scrolls into view.

Buttons fill with paint

For designers

In Figma prototypes, use Smart animate with these durations and name the token in the annotation (--dur-wash, --ease-settle). Don't prototype content that fades in: in the build, it won't.

art-header

The sticky page header, and the standard navigation: a wordmark, a link per section, and the hero's drips on its bottom edge. It takes the hero's drips along when the hero scrolls away and leaves them on the hero when you scroll back. Voice

The paint puns stay in the frame: token names, component names, this page. The words people act on stay plain.

Do

  • Write in sentence case: "See my work".
  • Name buttons after what happens: "Send message".
  • Keep the same verb all the way: "Send message" leads to "Message sent".
  • Say what went wrong and how to fix it: "That email address is missing an @".

Don't

  • Put puns on buttons: "Brush it off" can't tell you what it does.
  • Write labels in capitals or add arrows to link text.
  • Apologise in errors, or blame the reader.
  • Use colour as the only signal for a status.

Setting up Figma

  1. Install the fontsInstall the three families from fonts/ before opening any file, so text doesn't fall back.
  2. Import the variablesMake a Primitives collection, a Size collection (modes Mobile and Desktop), and a Color collection per theme with one mode per paint: Deep and 1 to 8. Import each file from tokens/figma/ into its mode. If you'd rather keep aliases, load tokens-studio.json in the Tokens Studio plugin instead.
  3. Create the text stylesLoad tokens-studio.json in the Tokens Studio plugin and create text styles from its typography tokens: wordmark, heading-1 to heading-4, lead, body, small, label, button, code and signature. Use only these.
  4. Turn the assets into componentsDrag in the SVGs and make each one a component. Name components after the code: art-stroke/underline, art-button/secondary/l, art-tape.
  5. Design with roles, not pigmentsFill and text colours come from the Color collection (surface, ink, accent). Set each section frame's mode to its paint (Deep, 1, 2…) and the colours inside follow. Switch to another theme's collection to change theme. Use pigments directly only for strokes, dabs and paintings.

Page anatomy

A page is a stack of painted bands, each a different colour. It opens with the sticky header and the hero in the deep paint. The sections in <main> take paints 1, 2, 3 and so on, in order. The last section and the footer use the deep paint again, so a page opens and closes in the same colour. The footer comes after </main>, and nothing follows it.

Drips are rare on purpose: a drip under every section is tiring, not fun. Only two things drip. The hero ends in an <art-drip> of its own. Its drips are not there at once: each waits a few seconds, then runs down on its own time. When the hero scrolls away, the header takes those same drips along without starting them again, and leaves them behind on the hero when you scroll back up. Further down, the header takes the paint of the section above the one you are reading. Each time it is repainted, the fresh paint drips again. Sections and the footer have straight edges.

Content inside a section stays within 68 characters per line; canvases, demos and the gitflow can go wider.

Rules to design by

Every frame

  • Every section is painted. Header, hero, last section and footer are deep; between them paints 1 to 8 in order, so no two sections share a colour.
  • Drips are rare: the hero ends in drips, the sticky header carries them down the page, and nothing else drips.
  • From 960px a section is two columns: title and intro on the left, content on the right.
  • One card everywhere: white, square corners, a soft shadow, no outline.
  • Nothing changes place on hover.
  • Beyond the drips, one loud thing per screen: a painted heading or a splatter.
  • Every piece of text uses one of the twelve text styles.
  • Animate decoration and responses only. Content never fades or slides in, and never waits.
  • Each theme is three pigments, no more: brand, partner and complement. The complement is the accent: use it sparingly.
  • Text on the deep paint is gesso white. Text on paints 1 to 8, on the partner and on tape is dark.
  • Body text at least 17px, nothing below 14px. Touch targets at least 44px.

Brushwork

  • Use the strokes from assets/. Stretch them horizontally as much as you like; keep their height.
  • Under a big heading, a stroke is about 15% of the type size. Under body text, about 40%.
  • A splatter never sits behind text.
  • Strokes and drips are decoration: the text above them must read without them.
  • Give a drip a thin edge in its own paint, a shade darker, so it reads on the next section.
  • Drips hang straight from the bottom edge of the hero or the header, in that band's paint, and never reach into the section after next. Narrow screens get fewer drips, never squeezed ones.

Handing off

Name layers after components and their attributes (art-canvas · pigment=complement · wet), and colours after variables, never hex. Mark motion with the motion tokens instead of drawing it. For a gitflow, list each entry's branch, colour and whether it's still open; the code paints the graph.

Install

Gesso installs straight from git, and every project picks its own theme. The built CSS is committed, so projects never build Gesso themselves.

Add it to a project

npm install github:artvandervennet/gesso#v1.1.0

The tag pins a release, so a project only changes when you bump it.

Load the styles and one theme

@import "@vandervennet/gesso/fonts.css";         /* self-hosted fonts */
@import "@vandervennet/gesso/core.css";          /* spacing, type, motion, paints */
@import "@vandervennet/gesso/base.css";          /* plain HTML */
@import "@vandervennet/gesso/layout.css";        /* the page anatomy: bands, sections, cards */
@import "@vandervennet/gesso/themes/harbour.css"; /* this project's theme */

ClassWhat it is
.bandA painted band of the page. Put data-paint on it.
.innerThe content of a band: centred, at most 80rem wide, with the page gutter.
.band-dripAn <art-drip> on the bottom edge of a band. Only the hero has one.
.hero, .lead, .actionsThe opening band: a large title, one sentence that says what this is, and a row of buttons.
.sectionA band with a title column and a content column from 60rem up. Inside it: .section-head (with .section-title and an optional .intro) and .section-body. The head stays in view while its section scrolls.
.proseRunning text meant to be read, a step larger than body text.
.cardThe one card: a raised surface with no outline, on --shadow-card. <art-canvas> looks the same.
.card-gridCards one or two wide. With an odd number, the first card takes the whole first row, so the last row never has a hole.
.field-row, .form-messageA field with its button beside it, and what the form says back.
.page-footerThe footer after <main>: same deep paint as the last section, no rule, the signature bottom right.

Everything in it sits in the cascade layer gesso.layout, so a project's own styles override it without extra specificity.

Write styles with Sass

Projects that use Sass get the tokens as functions and the breakpoints as mixins. A token that doesn't exist fails the build: space(5) is an error, because the 4px grid has no step 5.

@use '@vandervennet/gesso/scss' as *;

@include layers(components);     // Gesso's layers first, then site.components

@include layer(components) {
  .price {
    padding: space(4) space(6);
    font-size: step(1);
    color: role(ink-muted);
    @include card;
    @include from(wide) { padding: space(8); }
  }
}
BreakpointWidthWhat changes
small40remPhones end here.
compact48remBelow this, the header folds its links into a menu.
wide60remSections become two columns.
roomy72remRoom for something beside the content column.

Give a project its own theme

Write a recipe like the one in Themes and pigments, then build it into the project and import it instead of a built-in theme. The command checks every pairing and stops with an explanation if something fails.

npx gesso-theme theme.json --out src/styles/theme.css --hex design/theme.hex.json

Change Gesso itself

npm run build          # tokens, themes, contrast check, design kit
npm version minor      # bump and tag
git push --follow-tags
